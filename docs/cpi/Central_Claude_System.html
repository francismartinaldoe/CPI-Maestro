Overview

Permissions & Settings

The central setup defines a common permission baseline for all team members in .claude/settings.json. This removes repetitive confirmation prompts for routine work while enforcing explicit approval for destructive or shared-state operations.

How Protection Works

Decision flow
1
Claude Code attempts a file edit or git push Any write to a protected file or git push command triggers a PreToolUse hook.
2
PreToolUse hook fires protect-core-files.sh (file edits) or protect-git-push.sh (git push) is invoked automatically by the harness.
3
Hook reads CORE_TEAM environment variable The hook checks whether CORE_TEAM is set in the session environment.
4
If = "1" → action allowed (core team) The hook exits with code 0 and Claude Code proceeds with the action.
5
If not set → action blocked Hook exits with a non-zero code and prints a message directing the user to raise a change request with C5199126.
Core Intelligence Team Setup
Add to .claude/settings.local.json
{ "env": { "CORE_TEAM": "1" } }
⚠ Gitignored — stays local, never committed

Team members: no action needed. Simply clone the repository and start using Claude Code. All agents, commands, and Jira MCP queries are fully available without any additional setup.

Auto-sync hook: git-sync-check.sh runs on every prompt — Team auto-pulls; Core Intelligence Team receives an informational question before pulling.
