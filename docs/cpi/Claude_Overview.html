💡What is Claude Code?

Claude Code is the program intelligence workspace for the NextGen Cloud Selling () program at SAP + Accenture. It combines Claude Code (Anthropic's AI coding assistant) with a curated set of-specific agents, commands, and knowledge — all distributed via a single git repository.

Every team member clones one repository and gets immediate access to 13 specialist AI agents covering Solution Management, Delivery, Architecture, Testing, Risk, DevIT, and more. The workspace connects directly to SAP Jira via MCP, enabling live queries against SP, YOUR_JIRA_PROJECT, YOUR_JIRA_PROJECT,TEST,KDD, and DevIT projects.

The setup is zero-maintenance: a git hook auto-pulls the latest agents, commands, and knowledge before every prompt. There is nothing to configure — clone, authenticate Jira once, and start working.

🏗️System Architecture

The git repository is the single source of truth. Every team member's workspace auto-pulls on each prompt — agents, commands, and settings are always current before Claude processes any input.

End-to-End System Flow
🔄Git Sync — Every Prompt

The UserPromptSubmit hook fires before Claude processes any input. If the local repo is behind origin/main, it pulls automatically. Claude receives a summary of what changed.

Hook Execution Flow
ℹ️ Fast-forward-only pull (--ff-only) is used. If pull fails (e.g. unexpected local modification), the hook reports the error and Claude advises manual resolution. Protected files cannot be modified by team members, so pull conflicts are not expected in normal use.

⚙️Technical Background
Claude Code Subagent System

Agents in .claude/agents/ are markdown files with a YAML frontmatter block. Claude Code reads the description field to decide when to auto-spawn an agent. When spawned, the agent runs with its own context and system prompt.

---
name: -solution-manager
description: Use for capability backlog, WSJF scoring, quality gates...
---
Full system prompt with domain knowledge...
Slash Commands

Commands in .claude/commands/ are invoked via /name [args]. The file body is the prompt template; $ARGUMENTS is replaced with whatever the user types after the command name.

Permission Deny Rules (settings.json) — non-core members

For non-core team members, the following deny rules can be applied to prevent accidental Write/Edit on the central files. Core members do not need these rules — protection comes from git push access (only repo owner pushes) plus the auto-pull mechanism wiping any local edits on next prompt.

{
  "permissions": {
    "deny": [
      "Write(CLAUDE.md)",  "Edit(CLAUDE.md)",
      "Write(README.md)",  "Edit(README.md)",
      "Write(.claude/agents/**)",   "Edit(.claude/agents/**)",
      "Write(.claude/commands/**)", "Edit(.claude/commands/**)",
      "Write(.claude/settings.json)","Edit(.claude/settings.json)",
      "Write(.claude/hooks/**)",    "Edit(.claude/hooks/**)",
      "Write(/**)",             "Edit(/**)",
      "Bash(git push *)",           "Bash(git push)"
    ]
  }
}
