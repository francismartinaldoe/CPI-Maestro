What is?

SAP + Accenture joint program building a new Cloud Sales Operating Model for end-to-end Lead-to-Cash processes. Targets Cloud Runway customers with APR < €1M. Focuses on touchless, high-volume public cloud volume business using standardised T&Cs (MCCA) and automated processes (CMAT, PM410).

How to Raise a DevIT (SCV2)
  1. Create a User Story in YOUR_JIRA_PROJECT
  2. Comment all required information (see below)
  3. Label user story DevITRequest
  4. Tag [Team Member Name] & [Team Member Name] (Opportunity Mgmt) or [Team Member Name] & [Team Member Name] (Lead Mgmt)
  5. Once DevIT ticket confirmed: remove DevITRequest label; add DEV-IT label
How to Raise (All Other Systems)
  • Write email to PO with EA and Solution Architect in CC
  • Include all required information listed opposite
Required Information
  • Current situation: what leads to this request
  • Business need: why is this needed
  • Acceptance criteria: what the feature must fulfill
  • Business benefit when delivered
  • Impact when NOT delivered
  • RDD: Requested Delivery Date
  • Priority: VH / High / Medium / Low
  • Impacted release: go-live affected

  • No resolution after expected timeframe: DevIT SteerCo (monthly) for upper management escalation
🚩OSS Process (Product Defects)
⚠️ OSS is ONLY for SAP standard code issues. NOT for custom code bugs, data errors, or configuration problems.
Key Rules
  • SAP standard code issues → OSS ticket
  • Custom code / YOUR-TEAM-LABEL implementation issues → Bug in YOUR_JIRA_PROJECT
  • Data errors → NOT OSS
  • CPQ: can bypass support team and create incident directly
  • No resolution after 45 days → escalate to Very High priority
Jira Labels for OSS Items
  • OSS — applied when an OSS ticket has been raised
  • PRODUCT STANDARD ISSUE — confirms the issue is a standard product defect

⭐Golden Standard Rules (v1.4, 16 May 2025)
🚫 These rules are NON-NEGOTIABLE on Cloud Runway. No concessions permitted.
Customer & MCCA Rules
  • Target: APR < €1M — but APR > €1M customers CAN opt in
  • MCCA mandatory before any Cloud Runway transaction
  • MCCA signed in one click; stored in Icertis
  • No free-text fields; no modifications/redlining allowed
  • Complex deals → Traditional Runway (no split deals between runways)
Quoting & Pricing
  • No quote approvals required (CMAT + MCCA + automated policy enforcement)
  • Commercial model: PM410 (Subscription + Excess Use)
  • Subscription billed annually in advance
  • Excess use billed in arrears (monthly or quarterly)
  • Max 7 phases per contract; quantities can only increase
  • Phase-specific discounts: NOT allowed
  • Termination for convenience: prohibited
Payment & Invoicing
  • Payment terms: Net 30 (unless law requires different)
  • Single payment provider: Stripe (autopay + invoice)
  • Invoices by email only; print/mail or custom portals: refused
  • No non-standard, merged, split, or manual invoices
  • Third-party collection activated after 365 days overdue
Renewal Rules
  • Target: 95%+ Auto-Renewal
  • Default Renewal Type: Auto; Fallback: Active
  • Auto-renewal: match expiring term, rounded down to nearest 12-month multiple
  • Non-renewal notification: 1 month, non-negotiable
Provisioning & Fulfilment
  • All provisioning is customer-triggered (self-guided via SAP for Me)
  • Automated provisioning within 24 hours of customer trigger
  • Unified Services mandatory (Unified Provisioning + Unified Metering)
  • EMS mandatory for all commercial entitlements
Contract Rules
  • E-signature via DocuSign only (5 countries excl. Phase 1)
  • No contracts from one sold-to party billed to separate subsidiaries
  • Material statuses: A5 (GA), A7 (upsell/renewal only), A9 (EOL/Sunset)
  • EOL notification: 6–9 months before EOS; data deleted 3 months after EOS
CMAT Structure
  • Cloud Product: lowest sellable commercial set of functionalities
  • Edition: specific functionality level (good/better/best); upwardly compatible
  • Option: supplemental to Edition; cannot be sold standalone
  • Hard Bundle: fixed combination; Soft Bundle: curated
